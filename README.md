# Weiqi iOS

A **fully free** and **completely offline** native iOS Go (Weiqi) application powered by the KataGo engine. Unlike many other Go apps, the engine runs locally on your device, requiring no internet connection and providing unlimited play for free.

## Features
- **Interactive Go Board**: Custom-drawn 19x19 board with stone placement and move markers.
- **KataGo Integration**: Built-in AI using the high-performance KataGo engine via C++ interop.
- **100% Offline**: All AI computations happen on-device. No data usage, no latency, and privacy-focused.
- **Always Free**: No subscriptions or hidden costs. Play as many games as you want.
- **Game Modes**:
  - **I'm Black**: Play against the AI.
  - **I'm White**: AI plays first.
  - **Human vs Human**: Local multiplayer.
  - **AI vs AI**: Watch the engine play against itself.
- **Modern UI**: Built with SwiftUI for a smooth, native iOS experience.

## Performance Optimization (CRITICAL)

### 1. Build in Release Mode
The engine uses the **Metal (GPU)** backend via Apple's Metal Performance Shaders Graph (MPSGraph). To achieve maximum performance, run the app in **Release** mode.
- In Xcode, go to **Product > Scheme > Edit Scheme...**
- Select **Run** on the left.
- Change **Build Configuration** from `Debug` to **`Release`**.

### 2. Search Depth
The search is configured via `Weiqi/Assets/gtp.cfg`. The GPU backend delivers rapid neural evaluations directly on Apple Silicon.

## Development & Build Instructions

### Prerequisites
- **Xcode** 15.0+ (last verified with Xcode 27.0)
- **XcodeGen**: Install via Homebrew: `brew install xcodegen`

### Getting Started
1. Generate the Xcode project:
   ```bash
   xcodegen generate
   ```
2. Open the project:
   ```bash
   open Weiqi.xcodeproj
   ```

> `Weiqi.xcodeproj` is generated from `project.yml`. Change targets, settings and versions in
> `project.yml`, then run `xcodegen generate` again. `KataGoSwift-Swift.h` is generated by Xcode
> on every build (from `metalbackend.swift`/`metallayers.swift`); do not commit a copy of it.

## Testing

> 📋 **[TESTING.md](TESTING.md)** collects all of this in one guide: test inventory, how to run, the manual
> checklist, the release checklist and troubleshooting.

**Run the full test suite before every release.** A release is only allowed when
`scripts/run_tests.sh` ends with `ALL PASSED` and the manual checklist below is done.

### Test plan: `Weiqi.xctestplan`
The **Weiqi** scheme uses the test plan `Weiqi.xctestplan`. It runs every test (`WeiqiTests` and
`WeiqiUITests`) in two configurations:

| Configuration | Payment state | What it proves |
|---|---|---|
| **Free** | Unlock Elite Levels **not** bought (`WEIQI_PAYMENT=disabled`) | Everything works for free users; Advanced and Pro show the paywall |
| **Premium** | Unlock Elite Levels bought (`WEIQI_PAYMENT=enabled`) | Everything works for paying users; Advanced and Pro start and a Pro game plays |

The UI tests launch the app with that purchase state (`WEIQI_UITEST_PURCHASED=0/1`). Only Debug builds
honor it (`StoreManager`); Release/App Store builds always ask StoreKit. The real StoreKit purchase flow is
tested separately by `StoreTests` against Apple's local StoreKit test environment.

#### Run everything (required before release)
```bash
scripts/run_tests.sh
```
This regenerates the project. Then, on an **iPhone 17** and an **iPad mini (A17 Pro)** simulator (iOS 26.2),
it runs the test plan in both configurations, **Free** and **Premium**. Finally it builds the **Release**
configuration for real devices, which is what App Store archives use, and checks that the built app has the
version from `project.yml` and none of the Debug-only test hooks. It prints PASS/FAIL/skipped per test and per
run, and ends with `ALL PASSED` or `FAILED: ...`.
- Other simulators: `scripts/run_tests.sh "iPhone 17 Pro" "iPad Air 11-inch (M3)"`
- Another simulator iOS version: `OS=26.0 scripts/run_tests.sh`
- One configuration only while iterating: `CONFIG=Premium scripts/run_tests.sh` (or `Free`)
- Skip the device build while iterating: `SKIP_DEVICE_BUILD=1 scripts/run_tests.sh`
- Logs and result bundles: `build/TestResults/` (open `*.xcresult` in Xcode to see failures and the
  screenshots attached by `testCaptureHandicapScreens`, `testPaymentGatesAdvancedAndProLevels`,
  `AnalysisUITests` and `LocalizationUITests`).

> [!WARNING]
> Don't test on the **iOS 27.0 simulator**. Its Metal driver fails an assertion inside Apple's MPSGraph
> (`MTLSimDevice newHeapWithDescriptor:`) as soon as KataGo evaluates the network, and the app aborts.
> This is simulator-only; real devices use a different driver. Use an iOS 26.x simulator, plus a real
> device for the manual checklist.

Expect about 75 minutes. The first run compiles KataGo, and the UI tests take about 15 minutes per simulator
and configuration because KataGo really plays the moves.

#### Run from Xcode or for one test
- Xcode: select the **Weiqi** scheme and a simulator, then **Product > Test** (⌘U). This runs both Free and
  Premium. The Test navigator shows results per configuration.
- A single test in one configuration:
  ```bash
  xcodebuild test -project Weiqi.xcodeproj -scheme Weiqi -testPlan Weiqi -only-test-configuration Premium \
    -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.2' \
    -only-testing:WeiqiUITests/GameplayUITests/testProGameWhenPurchased
  ```

#### Notes
- After adding a test file, run `xcodegen generate` (the script does this) or the new tests won't be in the project.
- The script boots each simulator and **uninstalls the app before every run**. Each run then starts as a new
  user, and the simulator's StoreKit test service never points at a replaced app build (that caused random
  "Unable to Complete Request" purchase failures). Any saved game on those simulators is removed.
- The UI tests start their own games, so they overwrite the saved game on that simulator.
- While the app hosts `WeiqiTests` it skips its own engine start-up (`GameView.onAppear`), so the tests
  have the engine to themselves.
- When you fix a gameplay bug, add a UI or engine test that fails before the fix and passes after it.

### In-app purchase setup (Unlock Elite Levels)
- **Product:** `com.cwave.weiqi.unlock_levels`, **Non-Consumable**. It unlocks Advanced (1000 visits) and
  Pro (2500 visits). The ID is in `Weiqi/StoreManager.swift` and must match App Store Connect (see
  `in_app_purchase_guide.md` for the App Store Connect steps).
- **Local testing:** `Weiqi/Products.storekit` defines the product (name, description in en/ja/zh, local
  test price $1.99). The real price comes from App Store Connect. `project.yml` attaches the file to
  the scheme's **Run** action, so **⌘R** in the simulator uses local StoreKit: buy, refund or delete
  transactions with **Debug > StoreKit > Manage Transactions**. The file is not copied into the app.
- **Edit `Products.storekit` only in Xcode's StoreKit editor.** If StoreKit can't decode the file, no
  product loads, and the only symptom is "Error decoding configuration file" in the simulator log. Before
  1.15 a hand-written `settings` block caused exactly this, so local purchase testing never worked.
  `StoreTests.testProductIsConfiguredAsNonConsumable` now catches it.
- **Device testing:** archives and TestFlight builds use the App Store sandbox. Sign in with a sandbox
  tester under **Settings > App Store > Sandbox Account**.

### Manual checklist (things the automated tests do not cover)
These checks need a person to look or listen. Do them on a real device when possible, otherwise on an iPhone
and an iPad simulator, using the Release build:
1. **Launch:** the splash screen gives way to the board. Settings shows the new version and build number.
2. **Turn indicator:** with *I'm Black*, *I'm White*, *Two Players* and *AI vs AI*, the turn ring and the
   "thinking" spinner follow the side to move.
3. **Payment, as a free user:** Easy and Amateur start immediately. Advanced and Pro show the lock and the
   purchase panel instead of START GAME. On a real device the button shows the App Store Connect price.
4. **Buying Premium:**
   - Simulator (⌘R, local StoreKit): **Unlock for $1.99** opens the purchase sheet; confirm it.
   - Real device: use a sandbox account or TestFlight.

   The lock and the banner disappear and Advanced/Pro start. Cancelling the sheet changes nothing.
5. **As a Premium user:** Pro thinks noticeably longer per move. The purchase is still there after
   relaunching the app. Reinstall and tap **Restore Purchases**, and it comes back. In the simulator, a refund
   in **Manage Transactions** locks Advanced/Pro again.
6. **Passing and score:** when KataGo passes you get a toast. After two passes "Counting score…" appears,
   then the Game Over dialog with a result like `B+3.5`, with dead stones and territory marked. The result
   should match a manual Chinese count: stones plus territory, minus 7.5 komi (0.5 with handicap, plus 1
   point for White per handicap stone).
7. **Sound and haptics** toggles in Settings work.
8. **Languages:** look through the `t18_*` screenshots in the result bundle, and check the main screen, the
   paywall and the toasts in Japanese and Simplified Chinese: no clipped or overlapping text.
9. **Memory on a device:** play 30 or more moves on Pro (or AI vs AI) with Xcode's memory gauge open.
   Memory must level off, not climb with every move.
10. **Update from the previous release** (optional, when the saved-game format or the handicap rules changed):
    install the previous release, start a handicap game and play a move, install the new build over it
    (`xcrun simctl install` keeps the data), and check that the game comes back unchanged.

## Release Checklist
1. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml` (never edit `Info.plist`,
   which reads them through `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)`), then run `xcodegen generate`.
2. Run `scripts/run_tests.sh` and get `ALL PASSED`: Free and Premium on iPhone and iPad, plus the Release
   device build, its version and the absence of test hooks.
3. Do the manual checklist above.
4. In Xcode, run **Product > Archive** (Release) and upload to App Store Connect.

## Architecture
- **UI Layer**: SwiftUI (`Weiqi/Views/`)
- **Bridge Layer**: Objective-C++ Wrapper (`Weiqi/KataGoWrapper.mm`)
- **Engine Layer**: KataGo C++ Source (`Weiqi/external/katago/cpp/`)
- **Backend**: Metal (GPU via Apple MPSGraph) with C++/Swift interoperability.

## Troubleshooting

### "AI is thinking..." stays forever
- Ensure you are in **Release** mode. In Debug mode, the engine can be 100x slower.
- If it still hangs, check the Xcode console. The engine might be stuck during model loading (though internal logs are silenced, critical errors may still appear).

### Updating the Model
To use a different KataGo model:
1. Replace `ios/Weiqi/Assets/model.bin.gz` with your new model.
2. Run `xcodegen` again if you renamed the file.
3. Update the filename in `GameView.swift` if necessary.
